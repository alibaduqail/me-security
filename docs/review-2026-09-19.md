# Review: 2026-09-19

Reviewed the policy model, saved data and grid migration, placement/removal, terminal lifecycle, server menus and payloads, storage/crafting mixins, optional wireless hook, client controls, item resources, and dependency declarations against AE2 19.2.17 and the established addon scope.

## Fixed findings

| Finding | Result |
| --- | --- |
| Placement collected all grids near the clicked block, even incompatible cable colors and unrelated side parts. | Checks now follow the destination host, cable color, exposed connection faces, and parts with an actual outward node. |
| Wrench removal checked every part in a shared block but missed an isolated part's outward grid. | Individual removal checks the selected part's internal and outward nodes, using AE2's player-dependent selection context. Whole-block mining still checks every part. |
| Cable recoloring bypassed Build and could merge two protected networks. | A required mixin authorizes the current network and prospective compatible neighbors before the color or topology changes. |
| Rejected placement returned before AE2's usual block-entity correction. | The server now resends block state and part data for the clicked and destination positions to undo client prediction. |
| The client discarded permission clicks while a prior edit was pending. Whole-mask edits also become stale after another change. | Individual permission toggles are applied in packet order to the current server policy. Owner authentication, trusted-target validation, valid single-bit checks, and revision checks for destructive/replacement edits remain enforced. Protocol is now 3. |
| Revoking Extract/Insert/Craft/Build left an open storage menu because View remained permitted. | Reducing permissions closes affected open AE2 menus; server actions still recheck permissions. |
| Item resources/documentation referenced an obsolete, absent composite face PNG. | The item uses its existing three masks, AE2's Fluix tint handler, and the monitor housing particle texture. |

The Security Terminal remains removable only by its owner. Ordinary Build permission never overrides that rule, including Creative mining. Standalone block protection remains outside this release's existing scope.

## Automated validation

- 50 JUnit tests passed, including every permission mask and complete saved-data round trips with player directory, chunk footprint, Build permission, and retired policy IDs.
- 12 dedicated-server GameTests passed both with and without AE2 Wireless Terminals 19.5.1.
- New regression cases cover disconnected cable colors and parts, denied item consumption, recoloring/revocation, recolor conflicts, an outward protected toggle-bus node, Creative owner/non-owner mining, rapid permission clicks, invalid toggle masks, stale-screen closure, verified cable split/rejoin, and crafting-context grid/revocation checks.
- Existing item/fluid tests exercise simulation and execution, denied actions preserving stored quantities, and machine automation on unpowered networks.
- Required mixins load during the tests. The optional wireless test forces its target through the transformer and verifies that the required patch was applied.
- The isolated GuideME client preview loaded a world and its recipes, verified the shipped page's navigation and item association, and compiled/opened the page without page-compiler errors. The preview waits for a loaded world because GuideME's recipe widgets and linked 3D pages require world data. This was a runtime validation, not a visual inspection of every layout element.

## GuideME integration

The page lives at `assets/ae2security/ae2guide/security_terminal.md`, is attached to AE2's Items, Blocks, and Machines navigation, and is indexed for the Security Terminal item. The screen has an AE2 help button. The guide covers the recipe, placement, trust, permission meanings, transfer confirmation, wireless access, automation, conflicts, and limits.

The integration follows [AE2's pinned addon guide documentation](https://github.com/AppliedEnergistics/Applied-Energistics-2/blob/neoforge/v19.2.17/guidebook.md) and GuideME 21.1.1 APIs supplied by AE2.

## Remaining manual coverage and limits

The tests use distinct server-side FakePlayers, not two graphical clients performing every interaction. They do not replace a complete live multiplayer exercise of wireless range/quantum transitions, every recipe-transfer and fluid-container shortcut, real chunk unload/reload and process restart, long-running crafting jobs, or packet latency with open screens. The client correction for ghost parts also needs a visual two-client check.

Policy and node serialization were inspected and saved-world records were round-tripped, but real chunk unloading across multiple dimensions has not been newly exercised in this review. Conservative associations can retain restrictions until previously connected chunks are available for reconciliation.

Build covers AE2 cable-bus parts, their recoloring and wrench removal, and player mining of their containing blocks. It does not secure standalone drives/controllers, storage-cell removal, external inventories/outputs, explosions, or arbitrary third-party tools and terminal integrations. Nonstandard connections (including later redstone or remote topology changes) may still produce the documented conflict state; that state denies player access until resolved.

Install the updated JAR on client and server, then restart all processes together because the payload protocol changed.
